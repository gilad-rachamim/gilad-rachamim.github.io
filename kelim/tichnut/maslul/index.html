מאיפה מתחילים?

שני מסלולים קצרים בעברית: אחד למי שרוצה להריץ AI על כרטיס NVIDIA, ואחד לסטודנטים להנדסת מחשבים שלומדים תכנות מקבילי וארכיטקטורה. בכל שלב – מושג אחד, תרגיל קטן, והכלי שעוזר.

לא צריך ידע קודם ב-GPU. צריך מחשב עם כרטיס NVIDIA (או חשבון בענן), ו-Python בסיסי.

להכיר את הכרטיס שלכם

לפני הכול: איזה כרטיס יש, כמה זיכרון, ואיזה דרייבר.

VRAM – הזיכרון שעל הכרטיס עצמו. הוא קובע איזה מודל בכלל נכנס. Compute Capability – הדור של הכרטיס (למשל 8.9 = RTX 40).

תרגיל: הריצו ורשמו את שם הכרטיס, כמה GB יש, ואת "CUDA Version".
nvidia-smi

CUDA – השפה והספריות של NVIDIA שמאפשרות לתוכנות להריץ חישובים על הכרטיס.

להבין למה זה מהיר (או איטי)

כדי לכתוב כל מילה, הכרטיס קורא את כל המודל מהזיכרון. לכן מהירות הזיכרון חשובה יותר מכוח החישוב.

טוקן – חתיכת מילה (בערך ¾ מילה באנגלית). רוחב פס – כמה GB הכרטיס קורא בשנייה.

לאמן משהו קטן משלכם (LoRA)

לא מאמנים מודל מאפס. לוקחים מודל קיים ומלמדים אותו משהו קטן – סגנון, נושא, פורמט – עם LoRA.

LoRA – במקום לשנות את כל המודל, מוסיפים לו "מתאמים" קטנים ומאמנים רק אותם. חוסך הרבה זיכרון וזמן.

תרגיל: חשבו כמה זמן ייקח לאמן מודל 3B על 2,000 דוגמאות בכרטיס שלכם.
זמן ועלות אימון ←לסדר את קובץ הנתונים (JSON) ←

מתאים לקורסים כמו תכנות מקבילי, ארכיטקטורת מחשבים ומערכות מחשוב. צריך C בסיסי, כרטיס NVIDIA ו-CUDA Toolkit (או Google Colab עם GPU).

מודל התכנות: grid, block, thread

קרנל (kernel) הוא פונקציה שרצה אלפי פעמים במקביל. כל הרצה היא thread, ה-threads מקובצים לבלוקים, והבלוקים ל-grid.

warp – קבוצה של 32 threads שמבצעים את אותה פקודה באותו רגע (SIMT). אם יש if שמפצל אותם – הם מחכים זה לזה (divergence).

תרגיל: חיבור וקטורים. שימו לב לבדיקה i < n – בלעדיה יש גישה מחוץ למערך.
__global__ void add(const float* a, const float* b, float* c, int n) {
  int i = blockIdx.x * blockDim.x + threadIdx.x;
  if (i < n) c[i] = a[i] + b[i];
}
// launch: add<<<(n + 255) / 256, 256>>>(a, b, c, n);

היררכיית הזיכרון

רגיסטרים (הכי מהיר, פרטי לכל thread) ← shared memory (משותף לבלוק, על השבב) ← global memory (ה-VRAM, גדול ואיטי יחסית).

coalescing – כש-32 threads של warp קוראים כתובות רצופות, הכרטיס מאחד אותן לקריאה אחת. קריאה "מפוזרת" יכולה להיות איטית פי כמה.

שאלה למחשבה: בכפל מטריצות, למה טוענים "אריח" (tile) ל-shared memory לפני החישוב?
תשובהכי כל ערך נקרא שוב ושוב על ידי threads שונים. טוענים אותו פעם אחת מה-global memory האיטי לזיכרון המשותף המהיר, וכולם קוראים משם. זה מוריד את מספר הגישות לזיכרון הגלובלי פי גודל האריח.
רוחב פס לכל כרטיס ←

Occupancy והסתרת השהיה

גישה לזיכרון לוקחת מאות מחזורי שעון. בזמן שwarp אחד מחכה, ה-SM עובר ל-warp אחר. כמה שיותר warps פעילים – יותר קל להסתיר את ההמתנה.

occupancy – כמה warps פעילים על SM מתוך המקסימום. מוגבל על ידי רגיסטרים, shared memory וגודל הבלוק.

תרגיל: במחשבון, הגדירו CC 8.9, בלוק של 256, 64 רגיסטרים ו-0 shared memory. מה מגביל? מה קורה ב-32 רגיסטרים?
תשובהב-64 רגיסטרים: הרגיסטרים מגבילים ל-4 בלוקים = 32 מתוך 48 warps (67%). ב-32 רגיסטרים: 6 בלוקים = 48 warps (100%).

אסינכרוני – המעבד שולח עבודה לכרטיס וממשיך הלאה בלי לחכות. השגיאה מתגלה רק בסנכרון הבא.

Roofline: חסום-זיכרון או חסום-חישוב?

לכל קרנל יש עוצמה אריתמטית – כמה פעולות חישוב לכל בייט שנקרא. אם היא נמוכה, הקרנל מוגבל ברוחב הפס, ואין טעם לשפר את החישוב.

Roofline – גרף שמראה את התקרה של הכרטיס: מהירות מקסימלית = min(כוח חישוב, רוחב פס × עוצמה אריתמטית).

תרגיל: מה העוצמה האריתמטית של חיבור הווקטורים (float)?
תשובהפעולה אחת (חיבור) על כל 12 בייט (קוראים 2 × 4 וכותבים 4) ≈ 0.08 FLOP/byte. רחוק מאוד מהנקודה שבה הכרטיס חסום-חישוב, ולכן זה קרנל חסום-זיכרון. אותו עיקרון מסביר למה מודלי שפה כותבים בקצב של רוחב הפס.
הדגמה: מהירות מודל שפה ←ncu ו-nsys למדידה ←

הדורות: מ-Volta עד Blackwell

כל דור הוסיף משהו: Volta – Tensor Cores ראשונים; Ampere – BF16 ו-TF32; Ada ו-Hopper – FP8; Hopper – Thread Block Clusters ו-TMA; Blackwell – FP4.

Tensor Core – יחידה שמבצעת כפל מטריצות קטנות בפקודה אחת. מכאן רוב הכוח של הכרטיסים ל-AI.
