# גשר טלפון↔מחשב – פרוטוקול (גרסה 1)

מיזם הכלים של גילעד רחמים. הטלפון (אפליקציית `com.hakelim.kelim`) שולח למחשב (תוסף הכרום `tools/chatima-ext`) קודי אימות ועוד, מוצפנים מקצה לקצה.
השרת (`gesher-worker.js`, Cloudflare Worker + Durable Object) הוא **ממסר עיוור**: מעביר בתים בין שני המכשירים של אותו צימוד, ולא יכול לפתוח אותם.

| קובץ | תפקיד |
|---|---|
| `tools/chatima-ext/gesher/crypto.js` | ההצפנה בתוסף (וב-node לבדיקות) |
| `kelim-android/.../gesher/GesherCrypto.java` | אותה הצפנה בטלפון (Java 8, בלי ספריות) |
| `tools/data/gesher-vectors.json` | וקטורי בדיקה משותפים – `node tools/check_gesher.js` (JS) ו-`GesherCryptoTest` (Java) |
| `tools/check_gesher_worker.js` | בדיקת השרת מקצה לקצה עם שני מכשירים מדומים |

## 1. מה השרת יודע – ומה לא

נשמר בחדר: תאריך יצירה, שימוש אחרון, SHA-256 של אסימוני הגישה, מונה מסגרות יומי.
**לא** נשמר ולא נרשם: תוכן, קודים, שמות שולחים, תור הודעות, כתובות IP (מלבד מונה ניסיונות צימוד לשעה), שום לוג. גם לא נשלח ל-Google Analytics.
אין תור בשרת: אם הצד השני לא מחובר, השולח שומר את ההודעה אצלו ושולח שוב כשהשני חוזר.

## 2. ה-QR

המחשב יוצר: חדר אקראי (16 בתים), סוד אקראי (32 בתים), זוג מפתחות ECDH P-256.
תוכן ה-QR:

```
https://hakelim.com/kelim/g/#<base64url של JSON>
{ "v":1, "r":<חדר b64u>, "s":<סוד b64u>, "k":<מפתח ציבורי של המחשב, 65 בתים raw, b64u>, "n":<שם המחשב>, "w":<כתובת השרת> }
```

הכול אחרי `#`, כך שהסוד לא מגיע לשום שרת גם אם מישהו פותח את הקישור בדפדפן. האפליקציה מזהה את הקישור ופותחת את מסך הצימוד; בלי האפליקציה, הדף מסביר איך להתקין אותה.

## 3. צימוד

```
pairToken = HMAC-SHA256(סוד, "hakelim-gesher-v1|pair")              32 בתים, b64u = 43 תווים
ph        = SHA-256(pairToken) hex
```

1. המחשב: `POST /pair {room, ph}` → `{ok:true}`. החדר פתוח לצימוד **3 דקות**. עד 30 ניסיונות בשעה לכתובת. חדר קיים → 409.
2. המחשב מתחבר: `GET /r/<room>/ws?tok=<pairToken>` ← `{t:'peer',on:false}`.
3. הטלפון סורק ומתחבר עם אותו pairToken (מחושב מהסוד שב-QR). שניהם מקבלים `{t:'peer',on:true}`. לקוח שלישי → 409.
4. הטלפון שולח מסגרת **בינארית גלויה** (UTF-8 JSON) – המפתחות ציבוריים, אין מה להסתיר:
   `{ "type":"hello", "pub":<מפתח ציבורי של הטלפון b64u>, "mac":<b64u>, "name":"Galaxy S26" }`
   `mac = HMAC-SHA256(סוד, "hakelim-gesher-v1|hello" ‖ חדר ‖ pubPc ‖ pubPhone)` – מוכיח שהטלפון ראה את ה-QR, ושהשרת לא החליף מפתח באמצע.
5. המחשב בודק את ה-mac (השוואה בזמן קבוע). לא תקין → מנתק ומציג QR חדש.
6. שני הצדדים גוזרים (סעיף 4), והמחשב שולח מסגרת טקסט: `{t:'seal', hPc, hPhone}` (SHA-256 hex של שני האסימונים).
7. השרת שומר את שני הגיבובים, מוחק את ph, שולח לשניהם `{t:'sealed'}` וסוגר את החיבורים בקוד **4002**.
8. כל צד מתחבר מחדש עם האסימון **שלו**: `GET /r/<room>/ws?tok=<tokPc|tokPhone>`. מעכשיו ה-QR הישן לא שווה כלום (403).

אחרי הצימוד כל מכשיר מציג את שם המכשיר השני. אפשר להשוות בעין (אין צורך במספר אימות, כי ה-mac כבר קושר את ה-QR למפתחות).

## 4. גזירת מפתחות

```
z   = ECDH(הפרטי שלי, הציבורי של השני)                          32 בתים
okm = HKDF-SHA256(ikm=z, salt=חדר, info="hakelim-gesher-v1", 128 בתים)
k12      = okm[0..32)    AES-256-GCM, מחשב → טלפון   (כיוון 1)
k21      = okm[32..64)   AES-256-GCM, טלפון → מחשב   (כיוון 2)
tokPc    = okm[64..96)   אסימון החיבור של המחשב (b64u)
tokPhone = okm[96..128)  אסימון החיבור של הטלפון (b64u)
```

בתוסף: k12/k21 נשמרים כ-`CryptoKey` שלא ניתן לחלץ (IndexedDB). בטלפון: ב-`EncryptedSharedPreferences` / Keystore.

## 5. מסגרת מוצפנת

```
[0x01][כיוון 1|2][מונה 8 בתים big-endian] ‖ AES-256-GCM(ciphertext ‖ tag 16)
nonce = 00 00 00 ‖ כיוון ‖ מונה          (12 בתים)
AAD   = חדר ‖ 10 בתי הכותרת
מונה  = max(הקודם+1, Date.now()·1000)    עולה תמיד, גם אחרי הפעלה מחדש, בלי לשמור לדיסק
```

המקבל זוכר את המונה האחרון שקיבל ודוחה מונה שלא גדול ממנו (`replay`). כיוון לא נכון או מסגרת קצרה → נדחית. כל שינוי של בייט → GCM נכשל.
גודל מרבי: 300KB למסגרת (השרת מחזיר `{t:'err',e:'size'}`), 20,000 מסגרות ביום לחדר (`quota`).

## 6. סוגי תוכן (ה-JSON שבתוך המסגרת)

| type | כיוון | שדות | שלב |
|---|---|---|---|
| `otp` | טלפון → מחשב | `id`, `code`, `src` (`sms`/`whatsapp`/`mail`/`app`), `app` (חבילת האפליקציה), `from` (שם השולח), `at` (ms) | 1 |
| `ack` | שני הכיוונים | `id` – המחשב קיבל (ואם מולא – `filled:true`) | 1 |
| `bye` | שני הכיוונים | – צד אחד מתנתק; השני מוחק את המפתחות שלו | 1 |
| `ping` | – | (טקסט "ping" → "pong", עונה Cloudflare בלי להעיר את החדר) | 1 |
| `clip` | שני הכיוונים | `text` – לוח משותף | 2 |
| `notif` | טלפון → מחשב | `id`, `key` (מפתח ההתראה באנדרואיד), `pkg`, `app` (שם האפליקציה), `title`, `text`, `icon` (data:image/png, 64px), `reply` (יש פעולת תשובה), `at` | 3 |
| `notif-x` | שני הכיוונים | `id`, `key` – נסגרה בצד אחד ← נסגרת/נעלמת בשני (בטלפון: `cancelNotification`) | 3 |
| `notif-reply` | מחשב → טלפון | `id`, `key`, `text` – מענה שהמשתמש הקליד; הטלפון שולח דרך RemoteInput ומחזיר `ack` עם `ok` (ואם לא – `why`: `gone`/`noreply`/`fail`) | 3 |
| `link` | שני הכיוונים | `url`, `title` | 3 |
| `file` | שני הכיוונים | `name`, `mime`, `part`, `parts`, `data` (b64) – חלקים עד 256KB | 4 |

סוג לא מוכר → מתעלמים (תאימות קדימה). שדה `src` חובה ב-`otp`: התוסף **תמיד** אומר לגילעד מאיפה הקוד הגיע.

## 7. נקודות קצה

| בקשה | תשובה |
|---|---|
| `GET /` | `{ok:true,name:'kelim-gesher',v:1}` |
| `POST /pair {room, ph}` | 200 / 400 קלט שגוי / 409 קיים / 429 יותר מדי |
| `GET /r/:room/ws?tok=` | 101 / 403 אסימון / 404 אין חדר / 409 מלא (בצימוד) / 426 לא WebSocket |
| `DELETE /r/:room?tok=` | 200 (סוגר את שני החיבורים ב-4003 ומוחק הכול) / 403 |

כתובת השרת החי: `https://kelim-gesher.gilad4049.workers.dev` (נפרס 17.11.2026, נבדק 41/41).
CORS פתוח (`*`) – התוסף לא צריך הרשאת מארח לשרת.

הודעות בקרה מהשרת (טקסט): `{t:'peer',on}`, `{t:'sealed'}`, `{t:'err',e:'seal'|'size'|'quota'}`.
קודי סגירה: `4000` חיבור חדש של אותו מכשיר החליף אותך · `4001` החדר פג · `4002` הצימוד הושלם, להתחבר מחדש עם האסימון · `4003` נותק.

## 8. חיים של חדר

- חדר שלא הושלם צימוד תוך 3 דקות – נמחק (alarm).
- חדר מצומד שלא היה בו שימוש 90 יום – נמחק. כל מסגרת / חיבור מעדכנים "שימוש אחרון".
- `DELETE` מכל אחד מהצדדים – נמחק מיד.

## 9. חיבור מחדש

- תוסף: WebSocket ב-service worker עם "ping" כל 20 שניות (שומר את ה-SW ער, כרום 116+), ו-`chrome.alarms` כל דקה שמחבר מחדש אם נפל.
- טלפון: מתחבר רק כשיש מה לשלוח (קוד חדש) או כשהאפליקציה פתוחה; מחזיק תור מקומי ושולח שוב עד `ack` (עד 10 דקות לקוד – אחר כך הוא כבר לא רלוונטי).
